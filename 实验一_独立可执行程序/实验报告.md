## 二、实验步骤

### 1. 创建 Rust 项目

进入已配置好环境的容器，进入 `/mnt` 目录：

```bash
cd /mnt
cargo new os --bin
cd os
cargo build
cargo run
```

### 2. 移除标准库依赖

#### （1）修改 target 为 riscv64

在 `os/.cargo/config` 文件中添加：

```toml
[build]
target = "riscv64gc-unknown-none-elf"
```

#### （2）修改 main.rs 文件

在 `main.rs` 开头添加：

```rust
#![no_std]
#![no_main]
```

实现 panic handler：

```rust
use core::panic::PanicInfo;

#[panic_handler]
fn panic(_info: &PanicInfo) -> ! {
    loop {}
}
```

删除 main 函数。

安装必要的组件：

```bash
rustup target add riscv64gc-unknown-none-elf
cargo install cargo-binutils
rustup component add llvm-tools-preview
rustup component add rust-src
```

#### （2）实现退出机制

```rust
use core::arch::asm;

const SYSCALL_EXIT: usize = 93;

fn syscall(id: usize, args: [usize; 3]) -> isize {
    let mut ret: isize;
    unsafe {
        asm!("ecall",
             in("x10") args[0],
             in("x11") args[1],
             in("x12") args[2],
             in("x17") id,
             lateout("x10") ret
        );
    }
    ret
}

pub fn sys_exit(xstate: i32) -> isize {
    syscall(SYSCALL_EXIT, [xstate as usize, 0, 0])
}

#[no_mangle]
extern "C" fn _start() {
    sys_exit(9);
}
```

#### （3）实现输出支持

```rust
const SYSCALL_WRITE: usize = 64;

pub fn sys_write(fd: usize, buffer: &[u8]) -> isize {
    syscall(SYSCALL_WRITE, [fd, buffer.as_ptr() as usize, buffer.len()])
}

struct Stdout;

impl Write for Stdout {
    fn write_str(&mut self, s: &str) -> fmt::Result {
        sys_write(1, s.as_bytes());
        Ok(())
    }
}

pub fn print(args: fmt::Arguments) {
    Stdout.write_fmt(args).unwrap();
}

#[macro_export]
macro_rules! print {
    ($fmt: literal $(, $($arg: tt)+)?) => {
        $crate::print(format_args!($fmt $(, $($arg)+)?));
    }
}

#[macro_export]
macro_rules! println {
    ($fmt: literal $(, $($arg: tt)+)?) => {
        print!(concat!($fmt, "\n") $(, $($arg)+)?);
    }
}
```

最终入口函数：

```rust
#[no_mangle]
extern "C" fn _start() {
    println!("Hello, world!");
    sys_exit(0);
}
```

## 三、思考问题

### （1）为什么称最后实现的程序为独立的可执行程序，它和标准的程序有什么区别？

**答：**

最后实现的程序被称为"独立的可执行程序"（freestanding executable），是因为它不依赖于任何标准库或运行时环境，可以直接在裸机或最小化的操作系统环境中运行。

**与标准程序的主要区别：**

| 特性 | 独立可执行程序 | 标准 Rust 程序 |
|------|----------------|----------------|
| 标准库依赖 | 无（`#![no_std]`） | 有（依赖 std crate） |
| 入口点 | `_start` | `main` |
| 运行时 | 无运行时依赖 | 需要 Rust 运行时 |
| Panic 处理 | 需自定义 `#[panic_handler]` | 标准库提供默认实现 |
| 可用功能 | 核心语言功能 + core crate | 全部标准库功能 |
| 运行环境 | 裸机、嵌入式、内核 | 有操作系统支持 |
| 二进制大小 | 通常很小 | 相对较大 |

### （2）实现和编译独立可执行程序的目的是什么？

**答：**

实现和编译独立可执行程序的主要目的包括：

1. **操作系统内核开发**：操作系统内核本身不能依赖标准库（因为标准库需要操作系统支持），必须使用独立模式编写。

2. **嵌入式系统开发**：在资源受限的嵌入式设备或裸机环境中，没有操作系统支持，程序必须独立运行。

3. **引导加载程序（Bootloader）**：系统启动时最早运行的代码，在操作系统加载之前执行。

4. **理解底层原理**：通过编写独立可执行程序，可以深入理解：
   - 程序的启动过程和入口点
   - 系统调用的实现机制
   - 内存布局和链接过程
   - 异常和中断处理

5. **最小化二进制文件**：在需要极小二进制文件的场景中（如 UEFI 应用、固件），独立可执行程序可以去除所有不必要的运行时开销。

6. **学习和研究**：对于学习操作系统、编译原理和系统编程的学生来说，这是理解计算机系统工作原理的重要实践。
